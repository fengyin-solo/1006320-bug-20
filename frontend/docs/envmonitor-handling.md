# 廊内环境监测链路处理说明

本说明同时出现在「廊内环境监测」与「运维值班交接」两个入口的交接事项语境里，两处口径一致。

## 1. 判定口径（全平台唯一一份）

四项指标由 `src/data/env-rules.ts` 的 `evaluateEnvReading` 统一判定，概览、列表、详情、上报、往期搬入、另存清单都引用它，概览不再另算（含氧气浓度）。

| 指标 | 合格区间 | 单位 |
| --- | --- | --- |
| 环境温度 | [5, 32] | ℃ |
| 空气湿度 | ≤ 85 | %RH |
| 氧气浓度 | [19.5, 23.5] | %VOL |
| 有害气体浓度 | ≤ 25 | mg/m³ |

- 四项全部有效且全部在限：`指标正常`，超标标记=正常。
- 任一指标越限：`指标超标`，超标标记=超标。
- 任一指标缺失或不可解析（空串、「未采集」「传感器离线」等）：`待人工确认`，**不计正常也不计超标**。

人工点「确认正常 / 标记超标」只接受与读数判定一致的结果；读数仍超标时点确认正常会被拒绝，超标标记不会被硬改掉。

## 2. 超标点位数怎么算（按点位重算，不累加）

- 以**监测点位**为单位，每个点位只认「采集时间最新」的一条记录（同时间以 id 大者为准）。
- 超标点位数 = 最新记录状态为「指标超标」的去重点位数。
- 确认正常时同一次落库同时改写：记录状态、读数、超标标记（`abnormal`）、`pending`，随后由同一口径重算点位状态。
- 同一点位重复确认直接拦截为「已是该状态」，异常数不会被再减一回。
- 概览页「廊内环境监测」一格的待处理=待采集点位数+缺项待确认点位数，异常量=超标点位数；与环境监测页看板、另存清单读到的是同一份台账。
- 另存清单（CSV）新增「超标标记」列，导出实时取台账当前值，不残留旧标记。

## 3. 存量记录回填（早年"未采集写成正常"如何区分）

存量数据按存储版本号触发一次性回填，回填时按采集时间从早到晚排序，逐条用统一口径重算：

- 读数一项都没有且状态是待采集：保留「待采集」。
- 有读数但不齐（含早年被误写成「指标正常」的记录）：改判为「待人工确认」，备注追加「缺项待确认：…」，加盖「存量回填」来源戳，进入缺项清单等人工确认。
- 读数齐全：按口径判为正常/超标，覆盖历史脏标志。

取舍：**不按正常默认，也不猜值**。缺项一律显式标成「待人工确认」，由人工逐条补录，避免把没采到数的记录继续当正常稀释异常率。

## 4. 重复上报

去重键 = 监测点位 + 采集时间（精确到分钟；只有日期的往期数据补 00:00）。

- 首次上报：正常接收，读数齐直接按口径判出正常/超标；读数缺转待人工确认。
- 再次上报：**只认第一次的内容**，首报读数与判定不变；后续与首报不同的指标值，按「字段: 旧→新（后续上报，仅备注）」逐条追加到首报记录的备注，不新增记录、不改变计数，并在交接清单留痕。

## 5. 往期数据按巡检日期整体搬入

- 入口在廊内环境监测页「往期数据搬入」。CSV 表头须含：监测点位、采集时间（巡检日期，`YYYY-MM-DD` 或 `YYYY-MM-DD HH:mm`）、环境温度、空气湿度、氧气浓度、有害气体浓度、监测人员。
- 先解析并校验**全部**明细：点位/时间为空、时间格式非法等任一明细致命错误 → 整批放弃，一条都不写。
- 同点位同时间与台账重复：跳过不新增，在台账原记录备注注明「仅保留台账原值」，导入结果返回跳过数。
- 明细落库后状态仍走统一判定；缺项转「待人工确认」。
- 搬入完成后返回：新增数、重复跳过数、缺项清单（记录号、点位、时间、缺哪些字段），并写一条交接事项。导入后立即重新读取台账，导入明细与台账现状一致。

### 缺项按哪种方式补（自行决定项）

**只接受人工逐条补录，不自动插值、不沿用历史读数。**

- 缺项记录在「缺项确认」弹窗里逐字段补；四项都补成有效数值后点确认才入库，仍按统一口径判定。
- 弹窗提供「取该点位上一笔读数」作为参考填充，但必须人工核对后提交，系统不替人做决定。
- 任一字段仍为空/非数值：整笔拒绝入库，不产生半条数据。

## 6. 落库失败整套退回

所有写操作（判定、上报、缺项确认、往期搬入、通用状态流转、交接事项追加）都走 `local-store.ts` 的 `commit` 事务：

1. 在内存草稿上完成全部改动；
2. entries / handover-notes / meta 三个键一起写入 localStorage；
3. 任一写入失败（配额、隐私模式等）：尝试把三个键恢复为提交前内容，缓存保持提交前快照，并向页面返回「落库失败，已整套退回」。

字段没落库的不会留在内存中间态，页面刷新后也见不到半成品。

## 7. 交接清单（两处入口一致）

交接事项只存一份（localStorage 键 `urban-utility-tunnel:handover-notes`），由 `src/data/handover.ts` 统一读写，`HandoverPanel.vue` 分别挂在：

- 廊内环境监测页底部；
- 运维值班交接页底部。

两处是同一个响应式数据源，内容完全一致。自动留痕的场景：超标/正常确认结论、重复上报差异、往期搬入汇总。
